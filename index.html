01 / Project case study

RiskLens

The problem

A report is hard to trust when its source data changes or its inputs cannot be recovered. RiskLens combines data investigation, correction review, and reproducible portfolio risk reporting.

What I built

  • Python CLI workflows for validation, portfolio calculations, investigation, report comparison, backtesting, and stress scenarios.
  • Immutable input snapshots, SHA-256 hashes, and saved report metadata for source-independent replay.
  • Correction approvals bound to parent and proposed input hashes.
  • Historical VaR and expected shortfall, rolling forecasts using preceding observations, and hypothetical instrument/sector shocks.

Engineering tradeoff

Retaining snapshots and review metadata adds storage and workflow complexity. It also makes a result traceable and lets the same inputs be replayed after upstream data changes.

Scope & evidence

Source code remains private. The illustration on this page explains the workflow; it is not an application screenshot or a statistical result. Historical estimates and hypothetical scenarios are investigation tools, not predictions of future losses.

 02 / Project case study

AI Revenue Brain

The problem

Real estate lead information can become fragmented across conversations and spreadsheets. The application brings lead context, matching, and next actions into one workspace.

What I built

  • A FastAPI backend and PostgreSQL data layer supporting a Next.js interface.
  • Lead context, intent signals, property matching, and next-action workflows.
  • Conversation, call, and site-visit briefs.
  • Dormant lead and objection analytics for examining pipeline patterns.

Design decision

Seeded leads let workflows be demonstrated without exposing client records. Separating the API and interface keeps business workflows accessible across application surfaces.

Scope & evidence

A private engineering project. The visual on this page is a workflow illustration. No customer revenue or conversion gains are claimed.

 03 / Project overview

Mental Health Chatbot

Technical focus

An educational NLP project exploring how different chatbot approaches respond to mental health FAQs. The repository includes examples of text processing, similarity-based responses, retrieval models, and sequence models.

Approaches explored

  • TF-IDF and cosine similarity for selecting relevant text.
  • Retrieval-based approaches using neural architectures.
  • Sequence modelling for generative responses.

Tradeoff & scope

Retrieval provides control over available responses. Generation offers flexibility but needs closer evaluation. No clinical effectiveness is claimed. See the public repository for setup requirements, original source acknowledgements, and notebook details.
